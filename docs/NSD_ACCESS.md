# Получение доступа к NSD — инструкция для тебя (я это сделать не могу)

## 1. Что такое NSD в двух абзацах

**Natural Scenes Dataset (NSD)** — самый большой на сегодня датасет «человек смотрит на картинки в
7-тесловом МРТ». 8 испытуемых, каждый провёл 30–40 сканирующих сессий по ~750 показов изображений.
Изображения — натуральные фотографии из COCO. Всего 73 000 уникальных картинок; каждый испытуемый
видел ~10 000 из них, по 3 повтора.

Ключевой для нас кусок — **shared1000**: 1000 изображений, которые показали **всем восьмерым**.
Это позволяет сравнивать испытуемых между собой на одном и том же стимульном наборе и делать
групповую статистику. Мы работаем только с ним.

## 2. Что тебе нужно подписать

NSD распространяется по лицензии, требующей явного согласия с условиями использования
(это данные людей — есть ограничения на реидентификацию и на редистрибуцию).

**Шаги:**

1. Открой **https://naturalscenesdataset.org**
2. Найди раздел **«Data access»** / **«Terms and conditions»** (на главной, в верхнем меню).
3. Заполни форму **NSD Data Access Agreement**. Там спрашивают:
   - имя, email, аффилиацию (укажи свою текущую — институт/компания; если независимый
     исследователь, так и напиши, это допустимо);
   - краткое описание планируемого использования — можно буквально:
     *"Representational similarity analysis comparing self-supervised vision transformer
     representations (DINOv2, CLIP, ViT) to human ventral stream responses, using the
     shared1000 stimulus subset. Academic research, results intended for a preprint."*
   - галочки согласия с условиями (не редистрибутировать, не пытаться реидентифицировать
     участников, цитировать Allen et al. 2022).
4. Отправь. Подтверждение обычно приходит на почту.

> Точные URL формы на сайте иногда меняются — ориентируйся на пункт меню «Data access»,
> он всегда ведёт на актуальную форму. Если не находишь — напиши мне, посмотрим вместе.

**Документация NSD** (очень пригодится, огромный подробный мануал): ссылка на «NSD Data Manual»
есть на том же сайте в разделе документации. Там расписан каждый файл в бакете.

**Цитировать обязательно:**
> Allen, E.J., St-Yves, G., Wu, Y., Breedlove, J.L., Prince, J.S., Dowdle, L.T., Nau, M.,
> Caron, B., Pestilli, F., Charest, I., Hutchinson, J.B., Naselaris, T., Kay, K. (2022).
> A massive 7T fMRI dataset to bridge cognitive neuroscience and artificial intelligence.
> *Nature Neuroscience*, 25, 116–126.

## 3. Что происходит после подписания

NSD физически лежит в **AWS Open Data**:

```
s3://natural-scenes-dataset/   (регион us-east-2)
```

Важно: технически бакет читается **анонимно**, без AWS-ключей — поэтому команда
`aws s3 ls --no-sign-request` может сработать и до подписания. Это **не значит**, что можно не
подписывать: соглашение — юридическое условие использования, и без него мы не имеем права
публиковать результаты. Подписываем и только потом качаем.

**Что мне прислать в чат, когда подпишешь** — просто:

```
NSD: подписал, подтверждение получил <дата>.
AWS: [нужны ключи / доступ анонимный, ключи не выдавали]
Свободного места на диске: NNN GB
```

Третья строчка нужна, чтобы я выбрал стратегию скачивания (см. §4).

Если AWS CLI ещё не стоит:
```bash
brew install awscli
```
Проверка доступа (после подписания):
```bash
aws s3 ls --no-sign-request s3://natural-scenes-dataset/nsddata/experiments/nsd/ --region us-east-2
```

## 4. Структура бакета — что мы качаем и что НЕ качаем

```
natural-scenes-dataset/
├── nsddata/
│   ├── experiments/nsd/nsd_expdesign.mat        ← КАЧАЕМ. Какой стимул в каком трайле,
│   │                                               какие индексы = shared1000
│   ├── experiments/nsd/nsd_stim_info_merged.csv ← КАЧАЕМ. Маппинг NSD id -> COCO id + crop
│   └── freesurfer/subjXX/label/*.streams.mgz    ← КАЧАЕМ. ROI-разметка (early/ventral/...)
├── nsddata_betas/
│   └── ppdata/subjXX/fsaverage/betas_fithrf_GLMdenoise_RR/
│       ├── lh.betas_sessionNN.mgh               ← КАЧАЕМ (это основной объём)
│       ├── rh.betas_sessionNN.mgh
│       └── lh/rh.ncsnr.mgh                      ← КАЧАЕМ. Для noise ceiling
├── nsddata_stimuli/stimuli/nsd/nsd_stimuli.hdf5 ← НЕ КАЧАЕМ ЦЕЛИКОМ (37 GB на 73k картинок).
│                                                   Берём 1000 картинок из COCO по crop-боксам
├── nsddata_timeseries/                          ← НЕ КАЧАЕМ. Сырые таймсерии, терабайты
└── nsddata_rawdata/                             ← НЕ КАЧАЕМ. Совсем сырое
```

### Почему `fsaverage`, а не `nativesurface` и не объём

- **`func1pt8mm` (объём, воксели 1.8 мм)** — «родное» пространство бет, но это 3D-сетка ~700k
  вокселей, из которых мозг занимает малую часть; файлы больше, и сравнивать испытуемых
  между собой можно только через дополнительную нормализацию.
- **`nativesurface`** — поверхность конкретного мозга, максимальная точность, минимум
  интерполяции. Но у каждого испытуемого своё число вершин, и групповой анализ по вершинам
  невозможен без переноса на общий шаблон.
- **`fsaverage`** — общий шаблон поверхности FreeSurfer, 163 842 вершины на полушарие,
  **одинаковые у всех**. Вершина №5000 — это анатомически одно и то же место у subj01 и subj08.
  Ценой одной интерполяции мы получаем прямую сопоставимость между испытуемыми и готовые
  ROI-маски в том же пространстве.

**Выбор: `fsaverage`.** Для RSA нам не нужна субвоксельная точность — нам нужны надёжные ROI и
возможность агрегировать по 8 испытуемым. Потеря от интерполяции здесь дешевле, чем боль
группового анализа в native-пространстве.

### Стратегии скачивания

Проблема: трайлы shared1000 **разбросаны по всем сессиям**. Нельзя скачать «файл с shared1000» —
его не существует. Отсюда две стратегии (переключаются в `configs/data.yaml`):

| | `stream_sessions` (по умолчанию) | `range_read` |
|---|---|---|
| как | качаем файл сессии → вынимаем нужные трайлы → удаляем файл | HTTP range-запросы: тянем только байтовые диапазоны нужных трайлов из `.mgh` |
| трафик, subj01 | **39 GB** | **3.9 GB** |
| трафик, все 8 | **279 GB** | **31.5 GB** |
| пик на диске | ~2 GB | ~0 |
| запросов к S3 | 1 на сессию (~80) | 1 на трайл (~6000 на испытуемого) |
| риск | нет, тупо и надёжно | нужно, чтобы `.mgh` был несжат и frame-contiguous — **проверено, так и есть** |

**Проверка формата (2026-08-10, реальный `head_object` + чтение заголовка):**
`lh.betas_session01.mgh` = 491 526 300 байт. Заголовок MGH: version 1, dims 163842×1×1,
nframes 750, datatype **3 = float32**. Значит: 284 байта заголовка + 750 × 163842 × 4 байта
данных + 16 байт хвоста. Файл **не сжат**, и данные лежат по-кадрово: трайл `f` — это
непрерывный блок `[284 + f·655368, 284 + (f+1)·655368)`. Ровно поэтому `range_read` реализуем.

> Замечание на будущее: документированное для NSD хранение бет в int16 со скейлом /300
> относится к **объёмным** (`func1pt8mm`) бетам. Поверхностные fsaverage `.mgh` — float32.
> Единицы (% сигнального изменения) перепроверим на S1 по распределению значений.

План: пилот на subj01 через `stream_sessions` (39 GB, тупо и надёжно), проверяем весь
пайплайн до S3 включительно. Затем для остальных 7 переключаемся на `range_read` —
разница 279 GB против 31 GB того стоит.

Точные цифры **до** скачивания:
```bash
make s0-estimate
```
